📐 假設模型與計算方式 點擊收合
🕘 佔用計算
  • 每位旅客典型於 STD 前 90 分鐘進場，STD 前 30 分鐘離場
  • 典型停留時間約 60 分鐘
  • 某小時的佔用人數 = 所有停留窗口涵蓋該小時的航班預估人數加總
⚠️ 溢流判定
  • 桌位總數由座位表分桌計算（現況 T1 25 桌、T2 25 桌）
  • 預估旅客人數會除以 1.6（平均每桌人數）轉為桌位需求
  • 溢流桌數 = max(0, 該小時桌位需求 − 桌位總數)
  • 當預估溢流時，建議提早調度或引導至其他航廈貴賓室
🎯 使用方式
  • 點右方數字輸入框直接改預估人數，變更即時儲存並同步給團隊
  • 「✨ 自動估算」用倒推分配：每小時容量 ÷ 該時段航班數，取最小
  • 「⚙️ 校準」可調 3 個核心參數，讓推估越用越貼近實際
  • 今日 / 明日的預估人數分開儲存，不會互相覆蓋
📌 舉例說明
  • JX121 STD 09:55 → 該航班旅客停留窗口 08:25 – 09:25
  • 會影響 08:00 和 09:00 兩個小時的佔用預估
  • 若該航班預估 12 人，這 60 分鐘就會佔用 12 席
資料來源：航班從 flights 表（TDX 每 5 分鐘同步），預估人數存 capacity_forecast 表。明日班表沿用今日班表為基準（星宇每日排班穩定）。停留窗口參數可調整程式碼中的 LOUNGE_ARRIVAL_BEFORE_STD 和 LOUNGE_DEPART_BEFORE_STD。

什麼時候用這個？
當所有 admin 都忘記密碼、或沒設安全問題時，需要有 Supabase Dashboard 存取權的人員（通常是 IT）到 SQL Editor 執行下方指令。
Step 1 · 登入 Supabase Dashboard
左側點 SQL Editor → + New query
Step 2 · 貼上並執行以下 SQL 
-- 重設 admin 密碼為 admin123（登入後強制改）
UPDATE users
   SET password_hash = crypt('admin123', gen_salt('bf', 10)),
       must_change_password = TRUE,
       is_active = TRUE
 WHERE username = 'admin';

-- 若要重設其他帳號，把 'admin' 改成該帳號
-- 若要重設安全問題（避免鎖住），追加：
-- UPDATE users SET security_locked_until = NULL,
--                  security_failed_attempts = 0
--  WHERE username = 'admin';
Step 3 · 用 admin / admin123 登入
登入後系統會強制你改密碼。強烈建議接著到「⚙️ 設定 → 🔐 安全提示問題」設好，之後就不用再走這條路。
