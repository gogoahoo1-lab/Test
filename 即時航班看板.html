開啟後，每輪 TDX 抓取完成時會檢查：所選範圍當天的檔案還沒下載過就自動存一份，同一天只會下載一次。 檔名為 航班資料_YYYY-MM-DD.json，可用「資料匯入」的讀入資料檔接回來。 瀏覽器第一次可能會問「是否允許此網站下載多個檔案」，要按允許；若你的瀏覽器設定成「每次下載都詢問儲存位置」，建議關掉，否則自動下載會卡在對話框。 選「前一日」時，TDX 的「保留範圍」請維持全部，否則前一日資料會被清掉。

航班即時地圖

嵌入開源 ADS-B 即時航班地圖（預設 globe.adsb.fi），打開本頁會自動載入，切換機場或來源也會自動重新載入。此為社群營運的公開服務，非商業追蹤軟體。

怎麼用

目前檔案版本：2026-09-29g（盤旋偵測：轉降偵測、目的地天氣、背景監看、資料來源狀態、盤旋紀錄統計）。版本不符時請重新下載檔案，舊檔不會自動更新。

  • 桃園機場走「TDX 桃園機場」頁籤最省事：填 Client ID／Secret 後按立即抓取，到場與離場會一次抓齊。
  • TDX 的 $top 預設值只有 30 筆，不分頁就只會拿到 30 班。本頁已改成自動帶 $top／$skip 分頁抓到底。
  • 多場站：TDX 頁籤可同時勾 TPE／RMQ／KHH 等，抓回來的每筆航班都會標記「場站」，看板與班表分析都能依場站篩選，不會互相混在一起。
  • 「資料匯入」頁籤用於：TPE 以外的機場、歷史檔案回填、離線資料、或任何非 TDX 的來源。到場、離場兩支 API 分兩次貼即可，系統會累加。
  • 若來源沒有方向欄位（例如只有到場那支 API），把「方向判定」改成整批視為到場再匯入。
  • 去重規則：方向＋場站＋日期＋航空公司＋航班號 相同視為同一筆，後匯入的覆蓋舊的，所以同一天重複抓不會灌水。加上航空公司是必要的，因為 TDX 的 FlightNumber 常常只有數字（例如 0002），少了航空公司代碼，不同家的同號航班會互相蓋掉。
  • 「班表分析」上半部是 TDX 定期班表（/Air/GeneralSchedule/International、/Domestic）， 直接拿航空公司公告的每週飛行日展開成未來 7 天，預設只抓 JX。進頁自動載入，6 小時內用快取，可改代碼看別家。
  • 想知道某個航點有幾支航班號，把「彙整」切到依航點，表格會依航班號數由多到少排；航點篩選面板的數字也是同一個意思。勾起某個航點再切回依航班號，就只看那條航線的班表。
  • 下半部「觀測班表分析」是從實際抓到的到離紀錄推估的，跨越天數愈多愈準；兩者來源不同，數字不一定完全吻合。
  • 資料只存在這個分頁，關掉就沒了。要留存請按匯出資料檔，下次用讀入資料檔接回來。

可辨識的欄位

  • 航班號：FlightNumber、FlightNo、FlightID、班機編號
  • 航空公司：AirlineID、AirlineName、Carrier、航空公司
  • 排定時間：ScheduleArrivalTime、ScheduleDepartureTime、ScheduleTime、ExpectTime、STA、STD、表定時間
  • 實際／預估：ActualArrivalTime、ActualDepartureTime、EstimatedTime、RealTime、ATA、ATD、ETA、ETD
  • 航點：DepartureAirportID（到場的起站）、ArrivalAirportID（離場的目的站）、Airport、起站、目的地
  • 其他：Terminal、Gate、CheckCounter、BaggageClaim、AircraftType、FlightStatus、Remark、FlightDate

時間格式支援 2026-09-09T14:05:00+08:00、2026-09-09 14:05、14:05、1405、202609091405。時間一律當作當地時間，不做時區換算。

統計口徑

  • 準點：實際或預估時間與排定時間相差 15 分鐘以內；延誤：晚於排定 15 分鐘以上。沒有實際時間的航班不計入準點率。
  • 每週班次：該航班在資料中出現過的不同星期幾數量。同一天飛兩班同號航班只算一次。

準點分析

  • 月份下拉只會列出資料庫裡真的有紀錄的月份。TDX 即時航班只涵蓋前日／當日／次日，所以要看整月、要跟上月比，都得靠每天抓取累積。
  • 準點門檻預設 15 分內；計算基準預設只用實際時間，還沒起降的航班自然不列入。若想把預估時間也算進去，改成「實際優先，缺則用預估」，數字會比較樂觀。
  • 時段是依排定時間分時，所以「18 時特別容易延誤」指的是表定 18:00–18:59 的航班，不是實際在那個時間起降的航班。
  • 每個時段至少要有 3 班可比對，才會納入最容易延誤時段的排名，避免單一班次左右結論。
  • 要累積整月資料，請在「TDX 桃園機場」頁勾選每日自動下載存檔，並讓自動更新每天跑。TDX 只保留前日／當日／次日，沒存下來就永久拿不回。
  • 存下來的 航班資料_YYYY-MM-DD.json 可隨時用「資料匯入」的讀入資料檔接回來，可一次多選整個月的檔案，重複讀同一天不會重複計算。
  • 瀏覽器本機儲存約 5MB，所以只保存「本機保留天數」內的資料（預設 21 天），且以精簡格式存放。要看更早的月份，把當時的每日檔案讀回來即可——讀進來的資料在關掉分頁前都能分析。
  • 場站篩選固定列出 TPE、RMQ、KHH、TSA 四站（後面數字是資料庫裡的筆數，0 代表還沒抓過），其餘場站依實際資料出現。
  • 到離看板會自動判斷登機階段：離場航班、尚未起飛、距排定起飛 40 分鐘以內顯示「登機中」，15 分鐘以內顯示「最後登機」。TDX 不提供登機狀態，這是用時間推算的。若資料來源本身含有「登機中」「Boarding」「Final Call」等文字（非 TDX），也會直接辨識。正在登機的航班會浮到看板最上方的綠框置頂區，拿到實際起飛時間後自動消失。
  • 追蹤中的航班進入登機或最後登機時，也會推播到你的 Teams 中繼 URL。
  • 盤旋偵測進階功能：
    ・轉降偵測：航機接近目的地（250 浬內）或盤旋過後，持續 4 分鐘以上背離目的地、且比最接近時遠了 30 浬以上，標為「疑似轉降」，並依航向推算最可能的備降機場。轉回目的地會自動取消。
    ・盤旋分類：高度維持（±1,500 呎）或呈跑馬場形（兩個約 180° 轉彎＋直線段）才算盤旋；邊轉圈邊下降超過 3,000 呎列為「繞圈下降」（多為雷達引導，只列注意）。盤旋中會顯示預估延誤分鐘。
    ・目的地天氣：盤旋、轉降、注意中的航機會附上目的地 METAR（aviationweather.gov），含飛行類別、風、能見度、雲幕與強風／雷雨等警示；機場周邊模式另顯示監看機場的即時天氣。
    ・背景監看：擴充功能 v2.0 起可在背景每 30 秒偵測，關掉看板分頁也會推播 Telegram 並記錄事件（Chrome 需開著）。開啟後看板本身不再重複推播。
    ・資料來源狀態：列出各資料源最近成功／失敗、被限流或被擋，方便排查更新變慢的原因。
    ・盤旋與轉降紀錄：自動記錄每次事件（航班、時間、圈數、高度、結果、目的地天氣），提供時段與目的地統計，可匯出 CSV 用 Excel 開啟。
    ・航班資料 API（選用）：填入 AirLabs（最多 4 組金鑰自動輪替）或 FlightAware AeroAPI 的 API Key，每隔設定的間隔用一次整批查詢，更新監看範圍內所有航機的航線、機型、註冊號與位置。ADS-B 收不到的航班只顯示 API 實際回報、15 分鐘內的位置（標「API」），不做任何推估；超過 15 分鐘沒有新位置就不顯示。資料優先順序為 TDX 官方班表 ＞ API ＞ 社群資料庫。
    ・平滑移動：兩次更新之間依地速與航向推算，飛機在地圖上連續移動。
  • 盤旋偵測的資料來源：adsb.lol、adsb.fi、OpenSky 都不允許網頁直接跨站讀取，而且會擋 Cloudflare 等雲端主機，所以要透過下列其中一種方式：
    ① ADS-B 橋接 Chrome 擴充功能（推薦）：用你自己電腦的網路抓資料，裝好後不用任何設定，狀態列會顯示「擴充功能・adsb.lol」。只在安裝的那台電腦的 Chrome 有效；若是直接雙擊打開本機 html 檔，要在擴充功能詳細資料開啟「允許存取檔案網址」。擴充功能的設定頁可選填 OpenSky 帳號當備援。
    ② Google Apps Script 代理：把 adsb-proxy Apps Script 部署成網頁應用程式，網址填到「進階：自訂資料代理」。手機也能用，但 Google 的伺服器是否會被資料站擋下要實測。
    機場周邊每 15 秒更新（改用 OpenSky 時 30 秒）；指定航空公司依機型逐一查 adsb.lol，機型越多更新越慢，改用 OpenSky 全球資料時 90 秒一次。
  • 「航班地圖」頁上方的盤旋偵測每 15 秒從 airplanes.live（備援 adsb.fi）抓機場周邊航機位置，追蹤每架航機近 12 分鐘的航向。同一方向累積轉 240° 以上列為「注意」，滿一圈且高度 1,500 呎以上、未落地列為「盤旋中」，盤旋超過 15 分鐘或滿 3 圈列為「長時間盤旋」；squawk 7700／7600／7500 直接列最高級。呼號會換算成航班號（例如 SJX762 → JX762）並對照看板上的 TDX 資料。「監看方式」改成指定航空公司（全球）時，輸入 IATA 或 ICAO 代碼（例如 JX 或 SJX，最多 3 家），就會列出該公司全球所有空中航機並判斷盤旋。公開 ADS-B API 沒有依航空公司查詢的功能，所以是依機型抓全球航機、再用呼號前綴篩選：「查詢機型」會自動帶入該公司機隊（不在內建表的公司用 21 種常見客機），機隊有新機型時可以自己補上。每種機型查詢間隔 1.1 秒，機型越多更新越慢。勾「只列出盤旋／注意」可以只看有狀況的航機。飛往台灣的航班會顯示距目的地機場的距離，其他顯示經緯度；遠洋航段沒有收訊站時會暫時消失。只要監看開著，切到其他頁籤也會繼續偵測，「航班地圖」頁籤上會出現紅色數字。這是依航跡推算，偶爾會把繞飛天氣或雷達引導的大轉彎判成注意，請以塔台／簽派資訊為準。
  • 空位查詢：把訂位系統的 Flight Info 清單（含 Pax 已訂位 F/C/W/Y 欄）整段貼上，會自動換算台北時間（系統時間為 UTC 時勾選 +8）、依機型座位配置算出各艙空位，依台北出發日分組，美國線置頂並加總商務／豪經／經濟空位；超賣顯示紅色、經濟艙低於門檻顯示橘色。調機（P）與取消班次不列入。座位配置可在頁面內修改，遇到未知機型會提示填寫。貼上內容只存在這台電腦。
  • 到離看板的航班列表上方有區域按鈕（國內、東北亞、港澳大陸、東南亞、南亞、北美、大洋洲、歐洲、中東非洲、其他），依航點代碼判斷所屬區域，按鈕旁數字是目前條件下的班次數；再點一次或點「全部」即取消。區域篩選會跟方向、日期、狀態、場站、航空公司條件一起生效，關島、塞班歸在大洋洲。
  • 定期班表的「航點篩選」可依國家快速選取：展開面板後上方會列出目前航點涵蓋的國家／地區，點一下就勾選該國所有航點，再點一次取消；也可以在下方逐一勾選單一航點，兩種方式可以混用。
  • 各航班表的「可比對班次」門檻可調；準點率低於 60% 的航班會以紅底標示。

盤旋偵測設定

一般

即時性：OpenSky 全球快照（指定航空公司模式）

需要在 ADS-B 橋接擴充功能的設定頁填入 OpenSky 的 Client ID／Secret（帳號每日 4,000 點，查一次全球 4 點；匿名只有 400 點，不會啟用）。會依「今日剩餘點數」自動拉長間隔並保留 400 點，確保時段內不會用光；時段外、被限流或額度保留時自動改回 adsb.lol 輪查。
